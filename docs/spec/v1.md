# Spec: TokenMaster v1 — 多 Provider 本地 OpenAI 协议网关

> 状态：**ready-for-agent**（本环境未配置 issue tracker，规格以文件形式发布于仓库）
> 依据：CONTEXT.md 领域术语 + docs/adr/0001~0007 决策记录（2026-10-06 grill 会话产出）
> 参考项目解读手册：docs/reference/*.md（zcode-pool / deepseek-harness-codearts / antigravity-manager / commandcode-proxy）

## Problem Statement

我在 15 家 AI 编程服务（codearts、buddy、workbuddy、lobsterai、qoder、qodercn、trae、cline、loomy、raccoon、minimax、zcode、opencode、gemini、commandcode）各自持有账号与订阅额度，但每家只在自己封闭的客户端/IDE 插件里可用：协议互不兼容、无法用统一的 OpenAI 协议客户端消费；多账号要手动切换；额度分散在各家后台看不到全貌、临期作废无人提醒；部分 provider（如 zcode）还会在关键路径上弹验证码打断使用。

## Solution

一个 Windows 桌面应用 TokenMaster：在本地回环地址运行 OpenAI 协议兼容网关（附 Anthropic 协议扩展面），把 15 家 Provider 的账号聚合成令牌池。任意 AI 编程客户端把 base_url 指向网关、配上网关密钥，即可用统一的模型名访问全部 Provider 的额度；网关按模型名路由、多账号轮询、失败自动换号、按模型限流冷却，并在 GUI 里提供账号管理、用量账本、额度/签到/领取、日志诊断与接入说明。产品形态为 NSIS 安装包，中英双语，托盘常驻。

## User Stories

**安装与首次配置**
1. 作为用户，我想安装 TokenMaster 后首次启动看到引导配置（网关端口、生成网关密钥），以便一分钟内完成初始化。
2. 作为用户，我想随时在 GUI 里查看/重置/禁用网关密钥，以便轮换凭据或临时放开本机使用。
3. 作为用户，我想从非本机地址访问网关时必须携带网关密钥，以便默认安全。

**账号生命周期**
4. 作为用户，我想按 Provider 添加账号，GUI 根据该 Provider 的实际登录方式引导我（浏览器 OAuth 回调 / 设备码轮询 / 扫码或短信 / 手动粘贴 token/key），以便把已有订阅纳入令牌池。
5. 作为用户，我想手动粘贴 token/key 添加账号（GUI 按 Provider 提示所需字段与格式），以便导入已有凭据。
6. 作为用户，我想从本机 zcode-pool 的账号目录一键导入全部 zcode 账号，以便迁移存量数据。
7. 作为用户，我想在账号列表里看到每个账号的身份、额度/积分、token 过期时间、可用状态，以便掌握池况。
8. 作为用户，我想启用/禁用/重命名/删除账号，以便控制哪些账号参与轮询。
9. 作为用户，我想账号快到期时后台自动刷新凭据（到期前提前刷新），以便不掉线。
10. 作为用户，我想不可续期的账号（如 loomy 会话、zcode 静态 JWT）失效时得到明确提示，以便知道需要重新登录而不是等待自愈。

**令牌池与请求可靠性**
11. 作为用户，我想请求失败时自动换号重试（401/402/403 换号；429 按 Retry-After 冷却该账号并换号；超时可重试），以便单账号故障不影响使用。
12. 作为用户，我想限流按「Provider×模型×账号」粒度记录与解除，以便一个模型的限流不拖累整个账号。
13. 作为用户，我想「全部账号都限流」与「没有可用账号」报出不同的错误，以便判断该等待还是该补账号。
14. 作为用户，我想选择选号策略（先到期优先 / 剩余额度最多），以便按自己的目标消耗额度。
15. 作为用户，我想对 buddy/workbuddy/lobsterai/trae 这类有积分有效期的 Provider 按余额临期分档选号，以便优先消耗即将作废的积分。

**路由与协议**
16. 作为 AI 编程客户端，我想 POST /v1/chat/completions 发起流式（SSE）与非流式对话，以便标准 OpenAI SDK 直接接入。
17. 作为 AI 编程客户端（Anthropic 协议），我想 POST /v1/messages 完成流式对话，以便 Claude Code 类客户端直连。
18. 作为 AI 编程客户端，我想 GET /v1/models 拿到全部可用模型（provider/model 复合 id），以便发现能力。
19. 作为用户，我想用裸模型名按默认映射表路由，用 provider/model 前缀强制指定 Provider，以便平时省事、需要时精确。
20. 作为用户，我想在 GUI 里维护模型名映射表（裸模型名→Provider 默认路由），以便消解同名模型冲突。
21. 作为用户，我想 thinking/reasoning 输出被正确拆分与归一（think 标签拆分、reasoning 双名合并、effort 档位按模型能力归一），以便各客户端呈现一致。
22. 作为用户，我想上游返回的工具调用参数被安全归一（空参数不伪造、残缺分片合并），以便 agentic 客户端稳定运行。

**用量与账本**
23. 作为用户，我想每次请求记入账本（时间、Provider、账号、模型、token in/out、缓存命中、状态码、耗时、TTFB），以便事后审计。
24. 作为用户，我想按天/Provider/账号/模型聚合查看用量统计与趋势，以便发现额度消耗热点。

**额度运营**
25. 作为用户，我想看到各 Provider 的积分/余额/临期信息（额度徽标或列表），以便决定先消耗谁。
26. 作为用户，我想对支持签到的 Provider 手动一键签到或开启自动签到，以便不浪费每日积分。
27. 作为用户，我想 zcode 有可领套餐时 GUI 提示并支持领取（需要验证码时拉起验证码载体过码），以便套餐不白白过期。

**验证码**
28. 作为用户，我想 zcode 上游要求验证码（3007）时自动拉起 WebView 验证码载体完成过码并恢复请求，以便关键路径不被打断。

**出站代理**
29. 作为用户，我想配置全局出站代理（http/socks5）并可按 Provider、按账号覆盖，以便国际/国内上游各走各的网络路径。

**桌面体验**
30. 作为用户，我想中英文切换界面语言并即时生效，以便分享给不同语言习惯的同事。
31. 作为用户，我想关闭窗口时最小化到系统托盘、网关继续运行，以便后台常驻。
32. 作为用户，我想设置开机自启，以便重启后无需手动打开。
33. 作为用户，我想二次启动时唤起已有窗口而不是开新实例，以便状态一致。
34. 作为用户，我想在日志面板看到网关请求日志与错误诊断（哪个账号失败、为何换号、上游原始错误），以便排障。

**接入**
35. 作为用户，我想在接入说明面板看到主流客户端（Claude Code、Cline、Continue、Codex 等）的配置示例（base_url + 网关密钥用法），以便快速把客户端切到 TokenMaster。

## Implementation Decisions

**模块边界（遵循 ADR-0004）**
- 网关核心做成**不依赖 Tauri 运行时 的纯 Rust 库**（axum + reqwest + tokio）：路由、令牌池、协议转换、账本、刷新调度全部在此；Tauri 壳层只做 commands 桥接、托盘、子窗口、生命周期。
- Provider 适配器族：每家 Provider 一组实现（静态模型表 + 登录/刷新 + 推理适配 + 额度/签到），实现统一的 Provider trait（模型目录、流式推理、凭据刷新、额度查询、签到、限流状态上报）。
- 登录流按四类策略实现：本地回环回调 OAuth（codearts/lobsterai/trae/gemini）、设备码或 CLI flow 轮询（qoder/qodercn/cline/minimax/zcode）、扫码/短信本地页（loomy/raccoon）、手动粘贴（opencode/commandcode 等）。
- 前端 React 19 + antd，暗色主题，页面：仪表盘 / 账号（按 Provider 分组）/ 网关设置（端口、密钥、模型映射、选号策略）/ 用量 / 日志 / 设置（语言、自启、托盘、出站代理）/ 接入说明。

**协议转换**
- 内部采用规范化消息表示：OpenAI 面与 Anthropic 面都转换到内部表示，再由各 Provider 适配器翻译为上游格式；上游响应流统一经 SSE 消费层处理（首 token/空闲双阶段超时、think 标签拆分、工具参数归一化、reasoning 档位归一化）。
- 特殊机制按参考实现移植：qoder 请求体由 Qoder 客户端提取的 WASM 加密（Rust 侧用 wasmtime 执行同一 WASM）、响应剥信封；codearts 请求 SDK-HMAC-SHA256 签名；loomy HMAC-SHA1 签名；gemini 双层信封 + 字段字母序序列化 + Antigravity 客户端身份伪装；trae SOLO 载荷与自定义 SSE 事件；zcode/minimax 走 Anthropic Messages 形态；commandcode 私有信封 + 每 key 设备指纹（salt+HMAC 派生、周期上报）；opencode 账号槽 + 匿名槽平权轮换、免费模型全槽可用、按账号指纹派生 projectId。

**令牌池与调度**
- 选号管道：候选过滤（账号启用 + 该模型未被限流 + 模型未被拉黑）→ 选号策略（先到期优先/剩余最多，可切换；buddy 系四家叠加余额临期分档）→ 失败分类处理（换号重试上限 4；429 解析 Retry-After 记冷却；按 Provider×模型×账号记限流）。
- 刷新调度：30 分钟周期 + 启动立即一轮 + 新账号入池补刷新；「续期不看账号启用状态」；不可续期账号只探测回写。
- 网关密钥：sk- 前缀随机生成、加密持久化、GUI 可重置/禁用；回环来源按配置放行。

**存储**
- 数据目录 `~/.tokenmaster/`：设置、账号（AES-256-GCM 加密凭据；zcode 凭据保持与官方 enc:v1 格式兼容以支撑导入）、账本 JSONL（大小滚动）、缓存。全部原子写（临时文件 + rename）。
- zcode-pool 导入：读取其账号目录结构与加密格式（密钥派生方式照搬），转换为本项目账号。

**验证码载体（遵循 ADR-0006）**
- 按需拉起 Tauri WebView 子窗口作为过码环境，配验证码供应池与退避；无常驻浏览器进程。

**打包与分发**
- NSIS 安装包（currentUser 安装）；v1 不做自动更新。

## Testing Decisions

- 好的测试只断言**外部可观察行为**（HTTP 响应、SSE 事件序列、账本记录、状态变迁），不断言内部函数调用与结构。
- **缝 1（最高缝，主战场）**：网关核心 HTTP 契约黑盒测试——测试进程内直接启动网关核心（纯 Rust 库，无需 GUI/Tauri），监听回环随机端口；上游 Provider 用 stub HTTP server 扮演（按 Provider 协议回放预设响应）。覆盖：两协议面的请求/响应/SSE 正确性、鉴权行为、模型路由与映射、换号重试与限流冷却、账本记账、错误分类。
- **缝 2**：单个 Provider 适配器 vs stub 上游的协议细节测试（信封构造、签名、SSE 解析、刷新流）；对真实上游的 e2e 用环境变量闸门控制、默认跳过，消耗额度的用例需二次确认变量——沿用 deepseek-harness 的闸门模式。
- GUI 不做自动化测试，以手动验收清单覆盖（对应用户故事 1~35 逐条可勾选）。
- Prior art：deepseek-harness-codearts 的 261 个契约式单测（模块级 spec + 事故回归）与 e2e 闸门表；zcode-pool 的纯函数单测风格（解析/加密模块独立可测）。

## Out of Scope

（除以下明确排除项外，均属 v1 范围；边界依据 ADR-0007）
- auto 跨池智能路由（虚拟模型跨池选型）
- 邮箱池、批量自动注册、Outlook 收信链
- Web 管理台（网关吐 HTML 页面）
- 无头/CLI/服务化运行、docker 部署
- 多虚拟 key（按 key 绑定 Provider/限流/用量）
- 客户端配置一键写入（cli_sync）
- 自动更新
- 账号数据导出/备份（v1 仅导入）
- Antigravity-Manager / dsh 数据格式兼容导入
- OpenAI /v1/responses 对外面（不做承诺；架构不封死）
- 非 Windows 平台的构建与验证承诺

## Further Notes

- **许可**：直接复用 Antigravity-Manager（CC-BY-NC-SA-4.0）Rust 代码，仓库 LICENSE 已按同许可标注（ADR-0002）；其余三个参考项目为 MIT。
- **风险项**：①qoder 加密 WASM 在 wasmtime 下的兼容性需早期验证；②zcode 验证码页在 WebView2（非 chromium）中的环境指纹兼容性需实测；③各上游协议会漂移，参考实现需持续对照更新；④Windows 下凭据文件并发写的共享冲突需沿用「重试 + 原子写」经验。
- **建议实现顺序**：①搭 Tauri2 + React 脚手架与纯 Rust 网关核心骨架（OpenAI 面 + 一个 mock Provider 打通缝 1）→ ②池化/换号/限流/账本 → ③逐家 Provider（先有直接参考的：zcode、gemini、commandcode、trae、qoder，再其余）→ ④验证码载体、领取/签到、导入 → ⑤GUI 打磨、i18n、托盘、NSIS。
- **前置条件**：本机需安装 Rust 工具链（rustup + MSVC target）与 WebView2（Windows 10/11 自带）；Node 22 + pnpm 已就绪。
